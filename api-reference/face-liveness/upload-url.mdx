```
POST /v1/sessions/{session_id}/steps/face-liveness
```

Mints presigned S3 `PUT` URLs for the captured frames, a timeline file, and — optionally — a replay clip. You upload the bytes directly to the returned URLs; nothing is proxied through the API.

Call this after [`start`](/api-reference/face-liveness/create-session) has run for this session's `face-liveness` step.

## Request

### Path parameters

| Parameter    | Type   | Description                  |
| ------------ | ------ | ----------------------------- |
| `session_id` | string | The verification session ID.  |

### Headers

| Header         | Required | Description         |
| -------------- | -------- | -------------------- |
| `x-api-key`    | Yes      | Your API key         |
| `Content-Type` | Yes      | `application/json`   |

### Body parameters

| Parameter        | Type   | Required | Description                                                                                                     |
| ---------------- | ------ | -------- | --------------------------------------------------------------------------------------------------------------- |
| `action`         | string | Yes      | Must be `"upload-url"`.                                                                                          |
| `frame_count`    | number | Yes      | Number of captured frames to upload. **1–8** (at least 3 are needed to score).                                  |
| `clip_mime_type` | string | No       | Mime of an optional full-attempt replay clip — `video/mp4` or `video/webm`. An unrecognized mime yields no clip URL. |

### Example request

<CodeGroup>
```bash cURL
curl -X POST https://api.deepidv.com/v1/sessions/a1b2c3d4-e5f6-7890-abcd-ef1234567890/steps/face-liveness \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "action": "upload-url", "frame_count": 5, "clip_mime_type": "video/mp4" }'
```
</CodeGroup>

## Response

`200 OK`

Same envelope as [`start`](/api-reference/face-liveness/create-session) (`step_id`, `step_status`, `failure_reason`, `current_step`, `attempts_remaining`, `session_status`, `session_progress`), with the `liveness` object for `upload-url`:

| Field                 | Type     | Description                                                              |
| --------------------- | -------- | ------------------------------------------------------------------------ |
| `frame_upload_urls`   | string[] | Presigned `PUT` URLs, one per frame, in order. Upload as `image/jpeg`.   |
| `frame_keys`          | string[] | The S3 object keys the frames will occupy.                               |
| `timeline_upload_url` | string   | Presigned `PUT` URL for the timeline JSON. Upload as `application/json`.  |
| `timeline_key`        | string   | The S3 object key for the timeline.                                      |
| `clip_upload_url`     | string   | Present only when `clip_mime_type` was recognized. Upload the clip here. |
| `clip_key`            | string   | Present only when `clip_mime_type` was recognized.                       |

```json
{
  "step_id": "face-liveness",
  "step_status": "IN_PROGRESS",
  "failure_reason": null,
  "current_step": "face-liveness",
  "attempts_remaining": 3,
  "session_status": "PENDING",
  "session_progress": "STARTED",
  "liveness": {
    "frame_upload_urls": ["https://s3.amazonaws.com/…/frame_0.jpg?X-Amz-…"],
    "frame_keys": ["<org>/<session>/<session>/frame_0.jpg"],
    "timeline_upload_url": "https://s3.amazonaws.com/…/timeline.json?X-Amz-…",
    "timeline_key": "<org>/<session>/<session>/timeline.json",
    "clip_upload_url": "https://s3.amazonaws.com/…/clip.mp4?X-Amz-…",
    "clip_key": "<org>/<session>/<session>/clip.mp4"
  }
}
```

## The timeline file

`timeline_upload_url` must be `PUT` with an `application/json` body, but **the server does not currently parse or validate its contents** — scoring reads only the uploaded frames (the PAD model plus the frame-count/order checks described in [Complete Face Liveness](/api-reference/face-liveness/result)). There is no defined schema today; an empty JSON value such as `{}` or `[]` is sufficient to satisfy the upload.

<Note>
This is a placeholder in the current implementation, not a documented contract — a future release may start scoring on real per-frame timing/geometry data uploaded here (mirroring `FaceProbe.widthRatio` / `centerOffset` from the [Swift SDK](/integrate/sdks/swift/face-liveness)), which would change this section. If you're driving the flow through the iOS SDK's headless API instead of raw REST, you don't need to think about this at all — `checkMovementLiveness` uploads a placeholder timeline for you automatically.
</Note>

## Uploading the bytes

After receiving the URLs, `PUT` each artifact to its URL with the matching `Content-Type`:

- Frames → `frame_upload_urls[i]` with `Content-Type: image/jpeg`
- Timeline → `timeline_upload_url` with `Content-Type: application/json`
- Replay clip (if requested) → `clip_upload_url` with the same `Content-Type` you passed as `clip_mime_type`

```bash
curl -X PUT "$FRAME_URL" -H "Content-Type: image/jpeg" --data-binary @frame_0.jpg
```

<Note>
Only the frames and timeline are required to score. The replay clip is best-effort — a failed clip upload never affects the liveness verdict.
</Note>

### Errors

| Status | Meaning                                                                     |
| ------ | ----------------------------------------------------------------------------- |
| `400`  | Invalid body (e.g. `frame_count` outside 1–8).                                |
| `404`  | Unknown `session_id`.                                                         |
| `409`  | `FACE_LIVENESS_NOT_STARTED` — `start` hasn't run for this step yet.            |
