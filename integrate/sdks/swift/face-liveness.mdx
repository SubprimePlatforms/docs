---
title: Face Liveness (iOS)
description: "Add self-hosted, globally available face liveness to your iOS app — as a drop-in UI or fully headless with your own camera and UI."
---

The `DeepIDV` iOS SDK provides **custom face liveness**: self-hosted presentation-attack detection that works the same in every region. You can use it two ways:

- **Drop-in UI** — the SDK owns the camera, on-screen guidance, and both the movement and flashing-light challenges, and returns a result. One view, zero UI work.
- **Headless** — you own the camera and UI; the SDK contributes the face-geometry guidance, the scoring call, and (optionally) the replay recording. Movement challenge only.

<Info>
  Custom liveness is scored by the deepidv backend's PAD model as the `face-liveness` step of a verification session — see the [Face Liveness API](/api-reference/face-liveness/overview). The SDK orchestrates the start → upload → complete flow for you.
</Info>

## Requirements

- iOS 15.0+
- Swift 5.9+ / Xcode 15+
- Camera access — add an `NSCameraUsageDescription` entry to your app's `Info.plist` (e.g. *"Used to verify you're a real, live person"*). Without it, iOS kills the app the moment the camera session starts; the SDK cannot supply this for you since it's an app-level entitlement.
- A verification `sessionID` from a session created from a workflow that includes a Face Liveness step. The SDK never creates sessions — your backend creates it via [`POST /v1/sessions`](/api-reference/sessions/create-session) and hands the `sessionID` to your app.

## Install

Add the package with Swift Package Manager:

```
https://github.com/Deep-Identity-Inc/deepidv-sdk-swift
```

In Xcode: **File → Add Package Dependencies…**, paste the URL above, and pick the `DeepIDV` library product. Then import it:

```swift
import DeepIDV
```

## Configure the client

Create a `DeepIDVClient` with the custom liveness provider:

```swift
let client = DeepIDVClient(
    config: DeepIDVConfig(
        apiKey: "YOUR_API_KEY",
        livenessProvider: .custom
    )
)
```

<Warning>
There is currently no restricted, client-safe key type — `apiKey` is your organization's full secret key, and embedding it in a shipped app means it can be extracted from the binary. See [Authentication → Mobile apps](/authentication#mobile-apps-ios-sdk) for mitigations until a scoped mobile key exists.
</Warning>

The result of any liveness flow is a `FaceLivenessResult`:

```swift
public struct FaceLivenessResult {
    public let status: Status        // .succeeded / .inProgress / .failed
    public let confidence: Double?   // 0–100; nil until status == .succeeded or .failed
    public let passed: Bool          // server-computed against the workflow step's configured threshold
}
```

`passed` is computed by the backend against the pass threshold configured on the workflow's Face Liveness step (default `70`) — there is no client-supplied threshold anymore.

## Drop-in UI

`CustomFaceLivenessView` runs the entire attempt — camera, oval guide, "move closer" prompts, the flashing-light challenge, and the replay recording — and calls you back with the result:

```swift
CustomFaceLivenessView(client: client, sessionID: sessionID) { result in
    switch result {
    case .success(let liveness):
        print("passed:", liveness.passed, "confidence:", liveness.confidence ?? 0)
    case .failure(let error):
        print("liveness error:", error)
    }
}
```

The challenge played — movement, or movement + light — is whatever the `sessionID`'s workflow configured for its Face Liveness step; there's no `challengeType` to pass.

## Headless

When you own the camera and UI, drive the movement challenge yourself with three SDK pieces:

- `client.faceProbe(_:)` — per-frame face geometry to time your capture.
- `client.checkMovementLiveness(sessionID:frames:clip:)` — uploads the frames and returns the verdict.
- `client.makeMovementReplayRecorder()` — records the smooth replay clip for you.

### 0. Set up the capture session

`faceProbe` expects an **upright, front-camera** buffer in **32-BGRA**. Configure your `AVCaptureSession` accordingly before wiring up the delegate:

```swift
let session = AVCaptureSession()
session.sessionPreset = .high

guard let device = AVCaptureDevice.default(.builtInWideAngleCamera, for: .video, position: .front),
      let input = try? AVCaptureDeviceInput(device: device) else { return }
session.addInput(input)

let output = AVCaptureVideoDataOutput()
output.videoSettings = [kCVPixelBufferPixelFormatTypeKey as String: kCVPixelFormatType_32BGRA]
output.setSampleBufferDelegate(self, queue: DispatchQueue(label: "com.yourapp.liveness.capture"))
session.addOutput(output)

// Buffers arrive rotated to the sensor's native (landscape) orientation — rotate to
// portrait-up before calling faceProbe, or widthRatio/centerOffset will be measured
// against the wrong axis.
if let connection = output.connection(with: .video) {
    if #available(iOS 17.0, *) {
        connection.videoRotationAngle = 90 // portrait
    } else {
        connection.videoOrientation = .portrait
    }
}
```

Request camera permission (`AVCaptureDevice.requestAccess(for: .video)`) before calling `session.startRunning()`, and start/stop the session on a background queue — never on the main thread.

### 1. Read face geometry per frame

From your `AVCaptureVideoDataOutput` delegate, hand each frame's pixel buffer to `faceProbe`. It's stateless and local — no network:

```swift
let probe = client.faceProbe(pixelBuffer)   // FaceProbe { faceCount, widthRatio, centerOffset }
```

<Note>
`captureOutput(_:didOutput:from:)` fires on the queue you passed to `setSampleBufferDelegate` (not main). `faceProbe` itself is safe to call there — it's synchronous, local, and does no UI work. But if you use its result (e.g. the `prompt` string in step 2) to update SwiftUI/UIKit state, hop to the main actor first:

```swift
let (prompt, done) = capture.onFrame(pixelBuffer)
Task { @MainActor in
    self.promptLabel.text = prompt
}
```
</Note>

- `faceCount` — want exactly `1`.
- `widthRatio` — face width ÷ frame width (0–1). Bigger = closer.
- `centerOffset` — distance from frame center (0–1). `0` = centered.

Recommended thresholds match the SDK's own flow and are exposed as constants: `FaceProbe.centeredMaxOffset` (0.20), `FaceProbe.centeredMinWidth` (0.25), `FaceProbe.closeTargetWidth` (0.55).

### 2. Guide the capture (and record the replay)

Show "center your face" until centered, then "move closer" and grab a frame each time the face has grown since the last one — feeding every frame to the replay recorder along the way:

```swift
final class MovementCapture {
    private let client: DeepIDVClient
    private let replay: MovementReplayRecorder
    private var frames: [FileInput] = []
    private var centered = false
    private var lastWidth = 0.0

    init(client: DeepIDVClient) {
        self.client = client
        self.replay = client.makeMovementReplayRecorder()
    }

    /// Call from your camera delegate. Returns the prompt to show; a non-nil
    /// `done` means you've captured enough — run the check.
    func onFrame(_ pixelBuffer: CVPixelBuffer) -> (prompt: String, done: [FileInput]?) {
        let probe = client.faceProbe(pixelBuffer)
        guard probe.faceCount == 1,
              probe.centerOffset <= FaceProbe.centeredMaxOffset,
              probe.widthRatio >= FaceProbe.centeredMinWidth
        else { return ("Center your face", nil) }

        if !centered {
            centered = true
            frames.append(.data(jpeg(from: pixelBuffer)))
            lastWidth = probe.widthRatio
            replay.append(pixelBuffer)
            return ("Move closer", nil)
        }

        replay.append(pixelBuffer)                          // record every scan frame
        if probe.widthRatio >= lastWidth + 0.08 {           // real forward movement
            frames.append(.data(jpeg(from: pixelBuffer)))
            lastWidth = probe.widthRatio
        }
        return frames.count >= 5 ? ("Done", frames) : ("Move closer", nil)
    }
}
```

`jpeg(from:)` is your own encoder (e.g. `CIContext.jpegRepresentation`). The SDK accepts any `FileInput` — `.data`, `.fileURL`, or `.base64`.

### 3. Get the verdict

Finalize the replay and pass everything to `checkMovementLiveness`:

```swift
let clip = await replay.finish()   // SDK-encoded mp4 of the scan (nil is fine)
let result = try await client.checkMovementLiveness(
    sessionID: sessionID,
    frames: frames,
    clip: clip
)
if result.passed { /* live */ }
```

- Pass **3–8 frames in capture order**. Fewer than 3 throws `DeepIDVError.validation`; more than 8 is evenly down-sampled to 8.
- `clip` is optional — omit it to skip the replay. When present, the SDK uploads it as the session's operator replay (`Uploads.faceliveness_preview_clip`).
- Errors surface as `DeepIDVError` — `.validation` for bad input, `.network` / `.notFound` for endpoint failures.
- `checkMovementLiveness` drives the `start → upload-url → complete` action sequence against `sessionID`'s `face-liveness` step for you in one call — you don't need to call those REST endpoints yourself. The challenge type and pass threshold are owned by that session's workflow step config, not by this call.
- Call `checkMovementLiveness` once per attempt on the step. If it throws `.network`, it's safe to retry with a fresh set of frames — a retry issues a fresh `start` for the step.
- If the `sessionID`'s Face Liveness step is configured for the movement + light challenge, `checkMovementLiveness` throws `DeepIDVError.validation` after `start` — the light challenge requires the SDK to render full-screen color flashes, which the headless path can't do.

<Note>
The flashing-light challenge isn't available headless — it requires the SDK to render full-screen color flashes. Use the drop-in `CustomFaceLivenessView` for that.
</Note>
